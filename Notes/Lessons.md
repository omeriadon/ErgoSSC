# Lessons: the Learn tab

- `Lesson` (`Ergo/Lessons/Lesson.swift`) is every lesson, in order: its title, the question it asks, and the Library entries its summary links to (`LessonLink`, whose ids must exist in that category's JSON).
- `LearnRoute.lesson(Lesson)` pushes `LessonView` onto `NavigationManager.learnPath`, which is saved like the other tabs' paths. `LessonView` hides the back button: its toolbar close (`learnPath.removeAll()`) is the only way out, and the lesson keeps its place. On a lesson's summary the close button is a prominent checkmark.
- Each lesson's pages are in its own folder (`Behind the Words/`, `Fair Point/`, `The Bigger Picture/`), with a root view that switches on its saved page. Everything the person does is saved as it happens in that lesson's own state type, under its own Defaults key (`behindTheWordsState`, `fairPointState`, `biggerPictureState`), so a lesson reopens exactly where it was left. `Lesson.startOver()` resets it.
- `LessonSummaryPage` is every lesson's last page, over a dither in the accent colour, and its close button is a checkmark. Showing it adds the lesson to `lessonsFinished`. A lesson opens only once the one before it is finished (`Lesson.isUnlocked(finished:)`), and once all are, the Learn tab says so under the list. `Lesson.resetAll()` (a debug-only button in the Learn toolbar) starts everything over.
- The Learn tab is a card per lesson: a small picture (`LessonArt`), its title and question, and `Lesson.topics`, over a faint dither. In debug builds a card's menu can reset that one lesson.
- Animations that follow each other are spaced out (a delay on the second), so each one can be seen. Keep it that way in new pages.
- Lesson shapes are rounded rectangles, never capsules, and result text has no tick or cross icons.
- Every answer is authored, so checking one is deterministic. A model may only ever write around a result (like a line about a score), never decide it.
- What each lesson is and why is in `Plans/lesson-*.md`.
- Lesson 2's chat pieces (`ChatBubble`, `ChatConversation`, `ChatInbox`) are in `Fair Point/` and are reusable by any conversation. Its page 3 matches a scribble (or a tap) to Leo's bubbles by their frames in one named coordinate space, never by words, and only scrolls when the conversation doesn't fit, so the drag never fights a scroll. A mark beside a bubble is an overlay, outside the bubble's layout, so the bubble never changes width when it appears.
- Lesson 3's `BiggerPictureChart` (Swift Charts) uses years as categories, so zooming is only changing `visibleFrom`: the bars before it aren't drawn, and the y scale is fixed so the rest keep their heights. Page 2 zooms with a pinch, pinned to the last year. Every number the lesson shows (headlines, the usual line, the comparison) is computed from the data in `BiggerPictureContent`.

# Lessons: the Learn tab

- `Lesson` (`Squint/Lessons/Lesson.swift`) is every lesson, in order: its title, the question it asks, and the Library entries its summary links to (`LessonLink`, whose ids must exist in that category's JSON).
- `LearnRoute.lesson(Lesson)` pushes `LessonView` onto `NavigationManager.learnPath`, which is saved like the other tabs' paths. `LessonView` hides the back button: its toolbar close (`learnPath.removeAll()`) is the only way out, and the lesson keeps its place. On a lesson's summary the close button is a prominent checkmark.
- Each lesson's pages are in its own folder (`Behind the Words/`, `Fair Point/`, `The Bigger Picture/`, `Lucky Socks/`), with a root view that switches on its saved page. Everything the person does is saved as it happens in that lesson's own state type, under its own Defaults key (`behindTheWordsState`, `fairPointState`, `biggerPictureState`, `luckySocksState`), so a lesson reopens exactly where it was left. `Lesson.startOver()` resets it.
- `LessonSummaryPage` is every lesson's last page, over a dither in the lesson's own colour, and its close button is a checkmark. Showing it adds the lesson to `lessonsFinished`. Every lesson is open from the start, so any can be shown in a short demo, and they're listed in the order they're best done. Each card is glass tinted with the lesson's colour, with white text. Once all are finished, the Learn tab says so under the list, and coming back to it after finishing the last one scrolls down to that note. Every quiz card has 25 points of room under it. The line under a quiz score never opens with a greeting. `Lesson.resetAll()` (a debug-only button in the Learn toolbar) starts everything over.
- The Learn tab is a card per lesson: a small picture (`LessonArt`), its title and question, and `Lesson.topics`, over a faint dither. In debug builds a card's menu can reset that one lesson.
- Animations that follow each other are spaced out (a delay on the second), so each one can be seen. Keep it that way in new pages.
- Lesson shapes are rounded rectangles, never capsules, and result text has no tick or cross icons.
- Every answer is authored, so checking one is deterministic. A model may only ever write around a result, never decide it. `LessonScoreLine` is the one place it does: the line under a quiz score, written by the model on the device from which questions were right and wrong, greedily so the same results get the same line. Without the model, or if it fails, the lesson's own `scoreLine(for:)` shows.
- What each lesson is and why is in `Plans/lesson-*.md`.
- Lesson 2's chat pieces (`ChatBubble`, `ChatConversation`, `ChatInbox`) are in `Fair Point/` and are reusable by any conversation. Its page 3 matches a scribble (or a tap) to Leo's bubbles by their frames in one named coordinate space, never by words, and only scrolls when the conversation doesn't fit, so the drag never fights a scroll. A mark beside a bubble (`ChatMark`) sits to its right in the row, with its room always kept, so the bubble never changes width when it appears. On page 3, a scribbled message is named underneath instead (`ChatMessage.label`, like "Straw man"), with its room always kept: an unfair one in the accent colour with an outline to match, the fair one in grey. No red, green, ticks or crosses there, since red and green side by side read as both right and wrong.
- Lesson 3's `BiggerPictureChart` (Swift Charts) uses years as categories, so zooming is only changing `visibleFrom`: the bars before it aren't drawn, and the y scale is fixed so the rest keep their heights. Page 2 zooms with a pinch, pinned to the last year. Every number the lesson shows (headlines, the usual line, the comparison) is computed from the data in `BiggerPictureContent`.
- Lesson 4's four boxes (`FourBox`, `FourBoxGrid`) are always laid out the same way: the first thing's rows (yes, then no) and the second thing's columns (yes, then no), so `.both` is top left, the box people notice. Every count and rate is counted from `LuckySocksContent`, and each quiz answer is checked against its own data (`FourBoxCounts.holdsUp`). Page 1's games move into the grid with `matchedGeometryEffect`, so each card must be in only one of the two layouts at a time. It's the first lesson to link to biases (`LessonLink.category`).
